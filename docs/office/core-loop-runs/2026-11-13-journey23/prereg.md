# Journey 23 prereg — 交付了文件，就得有人签收

写于 2026-11-13，源码 `b3423e8`（D-5 修完），隔离工作区 `journey23`，免费模型 `beam-free`。

## 1. 这一轮要回答的问题

J22 一条消息就走完了环路，但**没有任何人看过交付物**：`complete` 在 `taskNeedsStructuredReview` 判假时直接 `markTaskDone`，而那个判据是对英文关键词做子串匹配，中文写 wiki 的 office 任务一个都不中。已修（D-5）：非人类 actor 关闭一个记着交付文件的任务时被拒，并指回 `submit_for_review`。

这一轮要把 J22 没测到的两件事跑到：

1. **被拒之后它会不会走正门**——`complete` 被拒 → `submit_for_review` → 决策卡（这是 D-5 的现场验证）。
2. **退回之后没有人提醒，它会不会自己重提**（J22 的 B1，当时因为根本没有卡而记未测）。

## 2. 场景

与 J22 同形，换路径（`team/reviews/j23-*`）与提交（本轮自己的 5 条）：

> Journey 23：把这批改动写成两页

> ② 对外说明 `team/reviews/j23-public.md`：3 条以内，人话，不出现 hash、不出现内部术语。

> 说完就去做，做完把这件事收尾，我要看到它进 done。

随任务给定：`git log --oneline -5` 输出（本轮生成）。

## 3. 操作员动作预算（≤4）

| 编号 | 动作 |
|---|---|
| H1 | 下达场景（一次，不留言） |
| H2 | 第一张计划卡：一句话回答受众与措辞 |
| H3 | 第一次交付后**退回一次**，理由具体 |
| H4 | 第二次交付后批准 |

**明确不做**：不告诉它去重提、不替它改状态、不在 Issue 上留言。H3 之后到 H4 之间**一个字都不发**——那段空白就是 B1 的判据。

## 4. 断言

| 编号 | 断言 | 读哪里 |
|---|---|---|
| C1 | 模型尝试 `complete` 被 `409` 拒绝，随后在同一回合内改走 `submit_for_review` | opencode `part` 表、`actions[]` |
| C2 | 至少一个任务进过 `decision`，卡正文列出交付文件（集合） | `requests[]` |
| C3 | **H3 之后无任何操作员消息**，`submit_for_review` 仍然发生 | `actions[]` 时间序 × `messages[]` |
| C4 | 重提后的卡不带 "has changed since this work was sent back"，且交付文件 sha256 与退回时刻不同 | 卡正文 + 文件哈希 |
| C5 | 终态 `done`，`review_state=approved`，0 次直写，0 条重复 lane | `tasks[]`、opencode `part`、wiki `git log` |
