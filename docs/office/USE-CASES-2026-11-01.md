# 使用场景菜单：这套办公室还能干什么（2026-11-01）

> 姊妹文档：`RESEARCH-2026-11-01-multi-agent.md`（架构判据的证据）。
> 本文只回答一个问题：**手上的 bot / routine / wiki / 任务链，还能接到哪些真实活儿上。**
> 每条都标了三件事：证据（谁在这么干、数字多少）、落到本 office 的形态、卡点。
> "卡点"是硬门槛，不是态度问题——过不去的就别排期。

## 0. 先看行业把时间花在哪（决定优先级，不是决定要不要做）

Anthropic 与调研公司 Material 对 500+ 技术负责人的调查（2026 State of AI Agents，2025 年底采样）：

| 事实 | 数字 |
|---|---|
| 已在跑**多阶段**工作流的组织 | 57%（其中 16% 已到跨职能流程） |
| 编码之外的最高影响场景 | 数据分析与报告生成 **60%**、内部流程自动化 48% |
| 未来 12 个月计划新增的最高场景 | **研究与报告 56%** |
| 已看到可量化回报 | 80% |
| 最大障碍 | 集成 46%、数据质量 42%、实施成本 43% |

对这套办公室的含义：**你已经在做行业里采用率最高、影响面最大的那类活（研究与报告）**。
剩下能加的不是"换个更花哨的活"，而是**把研究与报告的后半段补上**：跟踪、提问、复盘。
报告原文也点了这个方向——研究/报告类工作"建立了治理框架与内部能力，才让人敢把它推到更高风险的场景"。

## 1. 三条现成的作业可以抄

### 1.1 Anthropic 官方开源了一整套金融 agent（可整套搬方法论）

[`anthropics/financial-services`](https://github.com/anthropics/financial-services)（Apache 2.0，40.9k stars）
不只是 demo，是 **10 个端到端 named agent + 6 个 vertical plugin**，全部是 markdown/yaml，无构建步骤：

| 官方 agent | 干什么 |
|---|---|
| Market Researcher | 行业/主题 → 行业概览、竞争格局、peer comps、想法清单 |
| Earnings Reviewer | 财报电话会 + 文件 → 更新模型 → 出 note 草稿 |
| Meeting Prep Agent | 每次见人前的简报包 |
| Model Builder | DCF / LBO / 三表 / comps（直接改 Excel） |
| 其余 6 个 | GL 对账、月末结账、估值复核、LP 报表审计、KYC 筛查、Pitch |

`equity-research` 这一支的 9 个 skill 就是一份现成的"研究工作台"清单：
`earnings-analysis`、`earnings-preview`、`initiating-coverage`、`model-update`、**`morning-note`**、
`sector-overview`、**`thesis-tracker`**、**`catalyst-calendar`**、`idea-generation`。

结构上值得直接抄的一点：**skill 只在 vertical 里写一次，再打包进各 agent**（`scripts/sync-agent-skills.py` 同步），
且有 `check.py` 校验交叉引用与漂移。这与本仓库 `team/skills/*.md` 的做法同构，可以直接借它的校验思路。

### 1.2 社区版的补法：把"方法论"和"数据源"解耦

[`prof-little-bear/cc-equity-research`](https://github.com/prof-little-bear/cc-equity-research)（Apache 2.0）
把官方 9 个 skill 与 15 个社区 skill 接到**一个**数据 MCP 上，用四个入口路由 24 个 skill
（`/discover`、`/analyze`、`/monitor`、`/macro`）。

它指出的两个缺口，正是本办公室的两个缺口：
1. **官方 skill 只有方法论、不带数据**，得自己接连接器；
2. **没有"适配使用者"的层**——同一套 rigor，给不同人的语域不同（`style.md` 四个字段控制）。

第二点对本办公室尤其相关：cos 对内汇报 vs 对外简报，语气与详略本就该不同，现在全靠 prompt 里一句话。

### 1.3 一条把"简报"变成"流程"的模板

Marvin Labs 的财报季工作流是四段：**Ingest → Draft → Interrogate → Monitor**。
本办公室现在只有前两段（取数 → 写简报），没有 Interrogate（谁来挑错）和 Monitor（后来对不对）。
审阅回合正好补上 Interrogate；**Monitor 是空的**——这是下面 A1/A2 的来源。

另一句值得记的话（[FinRobot](https://github.com/AI4Finance-Foundation/FinRobot) 的项目自述）：
"Models can be replaced; the surrounding financial infrastructure — tools, workflows, validation,
provenance, and evaluation — is what makes the system reliable." 与本仓库判据 4 同向。

## 2. 场景清单

分层标准：**A = 现有骨架补一环就能跑；B = 需要新数据源；C = 需要新边界（外发/资金/权限）**。

### A 层：现有骨架补一环

#### A1. 论点台账：把"我说过什么"变成可复盘的数据

**画面**：每次简报里出现一个方向性判断，就落一条记录（标的、方向、依据、失效条件、复核日期）。
周五 routine 扫一遍到期条目，对照实际走势逐条打分：命中/未命中/条件已失效，并写一句"错在哪"。
月末出 `team/theses/month-<YYYY-MM>.md`——不是给读者看的，是给自己的记分卡。

**证据**：官方 `thesis-tracker` / `thesis-check` 就是这个形状；审阅回合已证明"换一个干净上下文去挑错"能出真发现，
而**挑自己过去的判断**比挑别人的交付更缺制衡，所以更适合做成 routine + 人工确认。

**形态**：`data-keeper` 或 `fund-invest` 的周 routine → artifact `team/theses/week-<date>.md`；
校验用 `command`（台账是 JSONL，可脚本判"每条都有 verdict 字段"）而不是人眼。
**卡点**：判断的"方向"要能被机器判对错，就必须给出**可判定的口径**（如"USD/JPY 周内收于 X 上方"）。
写不出可判定口径的判断，就不要进台账——这是判据 4 的直接应用。

#### A2. 催化事件日历：把"明天有什么"提前排好

**画面**：每周日晚一张 `team/calendar/<YYYY-Www>.md`——央行会议、数据发布、假期流动性、期权到期、
重要财报。每个事件带：时间（本地+UTC）、市场预期值、上次实际值、对本办公室在跟踪的论点的影响方向。
事件前 12 小时，bot 在 DM 里给一条"今天 20:30 CPI，你上次的判断是 X，注意 Y"。

**证据**：官方 `catalyst-calendar` skill；用例库里真实用户也是这个需求
（"扫我的 watchlist，找出受关税影响的标的、汇总评论、把候选加进表"）。

**形态**：现有 `cos`/`forex-watch` routine 扩一个 job → artifact 走 `wiki_artifact`；
判据可与"数据发布"流水线共用（见 A3）。
**卡点**：日历的准确性。现在 digest 只有前值/预期，没有 actual（`TODO-NEXT.md` P2 #5）——
日历能排期，但"预期值"要有可信来源，否则只是把猜测排成一列。

#### A3. 数据发布后的"观点更新"（宏观版 earnings-reviewer）

**画面**：数据一出（非农/CPI/利率决议），自动跑：数值 → 与预期差 → 对既有论点的冲击 → 要不要改 →
十分钟内产出 `team/briefs/<event>-<date>.md`，并**主动列出"我原来说过什么、现在是否还成立"**。

**证据**：官方 `earnings-reviewer`（电话会+文件 → 模型更新 → note 草稿）的宏观变形；
Anthropic 报告里"研究与报告"是最高采用方向，而它最有价值的部分正是**发布后的更新**而非发布前的猜想。

**形态**：事件驱动（不是 cron）——由 A2 的日历触发，`source_signal_id` 去重；
产出必须带"引用了哪条旧论点"（对应 A1 的台账 ID），否则退化成又一篇简报。
**卡点**：需要一个可靠的事件触发器。现在是人工/半自动，做到"真自动"要先有数据源（B1）。

#### A4. 会议/访谈准备包（10 分钟材料）— ✅ 已落地（2026-11-01）

**画面**：见一个人/听一场电话会之前，一页纸：对方最近说了什么（带日期与出处）、我方上次结论、
三个该问的问题、以及"如果他说 X，说明 Y"的分支。

**证据**：官方 `meeting-prep-agent`（profiler / news-reader / pack-writer 三个子代理）；
这与本办公室已有的"干净上下文"能力天然契合——准备包是**只读**产出，风险最低。

**形态（已实现）**：`python scripts/office/new_prep_task.py --who <对象> --date <日期>` 建单 →
playbook `team/playbooks/meeting-prep.md`（编译后即 `/skills` 里的 `meeting-prep`）指导写作 →
`team/prep/<slug>-<date>.md` → `command` 判据 `scripts/office/check_prep_pack.py` 卡四件事
（四节齐全 / 每条带日期+出处 / 问题 ≥3 / 分支 ≥1）。查不到的写「未收录」，不算违规，但整节
都是「未收录」会被拒。接口细节见 `RUNTIME-API.md` §9。

**卡点**：无。实测见 `RUNTIME-API.md` §9 的「实测」行。

#### A5. 文档与配置漂移巡检（把"文档腐烂"变成可测的事故）

**画面**：每周扫 wiki 与 docs 里引用的路径、命令、任务号、环境变量，逐个验证：
文件还在吗、命令还能跑吗、任务号还查得到吗。产出 `team/alerts/doc-drift-<date>.md`，
只列**已经失真**的项，不列"建议改进"。

**证据**：Doctolib 把 Claude Code 嵌进 CI，"每次代码变更触发 job 自动更新技术文档"
（Anthropic 报告案例）；本仓库已吃过同类亏——10-31 的 skill 归档只改了内存没落盘，
重启后复活，正是"看起来生效"的漂移。

**形态**：本仓库已有 `scripts/office/check-office-drift.ps1` 覆盖 scheduler/日志，
这条把它扩到"文档里的引用"；由 bot 每周跑一次，产出**带证据的失真清单**。
**卡点**：判据要好写——"路径不存在""命令退出码非 0""任务号 404"都是机器可判的。

#### A6. 周度自评：把审阅回合指向 bot 自己

**画面**：每周一次，由另一个 bot 以干净上下文读本周所有简报与判断，回答三个问题：
哪条判断没有依据、哪篇简报没有新增信息、哪次交付是在凑数。产出 `team/reviews/week-<date>.md`。

**证据**：审阅回合已验证同模型换干净上下文能出真发现（S3：每 PR 2 bug、58% 严重）；
把它从"审阅单件交付"提升到"审阅一段时间的产出"，成本仍是一轮。
**形态**：复用 `task_review.go`，只是被审对象从"一个任务"变成"一段时间窗"。
**卡点**：需要先有 A1 的台账，否则"判断"散落在聊天里，抓不出来。

### B 层：需要新数据源

#### B1. 一个结构化数据 MCP（替代"模型上网搜"）

**画面**：汇率、利率、宏观序列、日历事件从**一个**接口取，带时间戳与来源；
简报里的每个数字都能指回一条记录。

**证据**：`cc-equity-research` 的核心论点——官方 skill 是纯方法论，**数据连接器才是门槛**；
Anthropic 报告里"集成 46%、数据质量 42%"就是这条障碍。官方 11 个连接器（FactSet/LSEG/…）
每席位每年 $15–30K，个人用不起，所以社区才做了单 MCP 的替代。

**形态**：一个 MCP server + 一份 `team/data/` 落盘；所有 routine 从它取数，不再让模型自由搜索。
**卡点**：选源。可先做"只读、可缓存、带时间戳"的最小集（汇率 + 利率 + 日历），别一开始就追全。

#### B2. 持仓/自选组合的归因与预警

**画面**：每天一条"今天为什么动"——不是行情播报，而是把当日变动拆到因子（汇率、利率、商品、
个股事件），指出**与既有论点相反的那部分**。周度给一次"如果只做一件事，该做什么"。

**证据**：官方 `portfolio-monitoring` / `watchlist` / `event-radar`；用例库里有真实用户
每天用浏览器 agent 扫 watchlist、汇总讨论、更新表格。

**形态**：`fund-invest` routine → `team/portfolio/<date>.md`。
**卡点**：持仓数据要么手工维护一个文件，要么接券商导出。前者可行，后者要凭证——先用手工文件。

#### B3. 财报季流水线（若覆盖个股）

**画面**：财报前 preview（预期、关键指标、分歧点）；财报后 30 分钟内出更新 note，
并同步更新 A1 的论点台账。

**证据**：官方 `earnings-preview` / `earnings-analysis` / `model-update` 三件套，外加
`earnings-reviewer` agent（reader → model-updater → note-writer 三个子代理）。
**卡点**：需要财报原文与电话会录音/转写，成本与数据源都比宏观高一个量级。**本轮不建议**。

### C 层：需要新边界（不建议现在做）

- **对外沟通自动化**（账单谈判、保险申诉、订阅退订）：用例库里有大量真实成功案例
  （话费补偿、EU261 赔偿、宠物险理赔），形态都是"agent 准备 + 人点头发送"。
  本 office 目前**没有外发授权机制**，做这个等于新开一条安全边界，成本远大于收益。
  真想试，就从"只生成草稿、人手动发"开始。
- **自动交易**：用例库里有人在做（模型自主交易 $1k 组合），但与本仓库判据 1/4 直接冲突——
  它不可验证、不可回滚、且把最终写操作交给模型。**明确不做。**
- **多步采购/签约**：同上，写操作 + 不可逆。

## 3. 反面清单（比上面更值得记）

- **不要让 bot 自由上网搜数字然后写进简报**：这是 10-30 三处编造的直接成因；要么有数据源，要么写"未收录"。
- **不要给"看起来很忙"的 routine 排期**：判据写不死的活（"每天给点洞察"）只会生产噪音，
  且会稀释真信号——本仓库 10-31 的 scheduler 已经因为一次性 job 堆积埋掉过 9 个活 job。
- **不要在没有台账的情况下扩场景**：没有 A1 的记分卡，A2/A3/A6 都只是"更多的简报"，
  无法回答"这些 bot 到底让我变好了没有"。

## 4. 如果只做一件

**A4（会议/访谈准备包）**：只读、零新依赖、判据简单（文件存在 + 必须带出处与日期），
一轮 turn 的成本，复制现有 `wiki_artifact` 链路即可上线。

**如果做两件**，加上 **A1（论点台账）**：它是唯一能把"简报生产"变成"能力复利"的东西——
没有它，前面所有场景都只是产出更多文本；有了它，才有东西可复盘、可审阅（A6）、可触发更新（A3）。
